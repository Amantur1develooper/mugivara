# Обновление меню ресторана DUA — инструкция по запуску на сервере

## Что это

Новое меню ресторана **DUA** (все 3 филиала: Араван, Нурзаман, Фрунзе), составленное по
предоставленному PDF-меню, на трёх языках (RU/KY/EN), с фотографиями блюд, вырезанными
из самого PDF (для напитков без фото в PDF — подобраны обобщённые фото из тех же страниц
меню: чай, кофе, лимонады и т.д.).

**146 позиций** в **19 категориях**, из них **135 с фото**.

## Файлы

- `import_dua_menu.py` — скрипт импорта (Django management-скрипт, запускается напрямую)
- `dua_menu_data.py` — все данные меню (названия/описания RU-KY-EN, цены)
- `photos/` — 83 фотографии блюд (JPEG, ~4 МБ суммарно)

Все три файла нужно положить **в корень проекта на сервере** (`/var/www/mugivara/`,
рядом с `manage.py`) — так же, как лежат уже использовавшиеся `import_deniz_menu.py` и т.п.

## Как запустить

```bash
cd /var/www/mugivara
source venv/bin/activate   # активировать venv проекта

# 1. Сначала — сухой прогон, ничего не меняет в БД, просто печатает список:
python import_dua_menu.py --dry-run

# 2. Если всё выглядит верно — реальный запуск:
python import_dua_menu.py
```

Скрипт сам найдёт ресторан **DUA** по слагу (`slug__iexact="dua"`, так что регистр
не важен — сработает и на `DUA`, и на `dua`) и применит одно и то же меню
**ко всем филиалам ресторана одновременно** (Araван, Нурзаман, Фрунзе — они
находятся автоматически через `Restaurant.branches.all()`, отдельно указывать
их не нужно).

## Важно — как ведёт себя скрипт

- **Безопасно перезапускать** — категории и позиции ищутся/создаются по имени
  (`name_ru`), повторный запуск ничего не задублирует.
- **Старое меню не удаляется.** Скрипт только добавляет/обновляет. Если на сайте
  уже есть блюда со старыми/другими названиями — они останутся как есть, рядом
  с новыми. Если нужно "зачистить" старое меню — это отдельный шаг, который стоит
  сделать вручную через админку (или скажите — подготовлю отдельный скрипт).
- **Цены существующих позиций не трогаются** по умолчанию — если позиция с таким
  же названием уже была в БД, её цена не меняется. Добавьте `--update-prices`,
  чтобы принудительно обновить цены (`base_price` и `BranchItem.price`) у уже
  существующих позиций тоже.
- **Фото** прикрепляются только к позициям, у которых фото ещё нет. Добавьте
  `--overwrite-photos`, чтобы перезаписать даже уже существующие фото.
- Если фото прикреплять не нужно вовсе — `--no-photos`.
- Если нужно применить не к ресторану `DUA`, а к конкретному ID — `--restaurant-id 123`.

## Что было протестировано локально

Скрипт прогонялся end-to-end на тестовом ресторане в локальной БД (создание категорий,
позиций на 3 языках, фото, привязка к нескольким филиалам, повторный запуск —
идемпотентность подтверждена). Против самой продакшн-базы скрипт не запускался —
доступа к продакшн-серверу у меня нет, поэтому финальный запуск — за вами.
Рекомендую начать с `--dry-run`, затем прогнать на одном тестовом филиале
(`--restaurant-id` + `--branch-id`, если понадобится ограничить), и только
затем — на всех.

## Примечание не по теме DUA

Во время тестового прогона заметил: `Item.save()` в `catalog/models.py`
(функция `_compress_photo`) при пересохранении фото удваивает путь загрузки
(файл сохраняется как `items/photos/items/photos/<имя>.webp` вместо
`items/photos/<имя>.webp`). На отображение это не влияет (путь просто
не самый аккуратный), но если захотите — могу поправить отдельным разом,
это не связано с меню DUA и не блокирует этот импорт.
